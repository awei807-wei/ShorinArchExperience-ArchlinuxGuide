## 编码风格
- 生产界面优先使用 Quickshell/Qt 原生能力，不解析可本地化的人类可读命令输出来建立长期数据模型。
- 系统状态模型与显示逻辑分离；可独立验证的过滤、排序和标签规则放入纯 JavaScript 辅助模块。
- 不以静默回退掩盖系统能力缺失；加载、空值和错误状态必须保留稳定布局或明确占位。

## 命名规范
- PipeWire 输出统一称为 `audioOutput` 或“音频输出设备”，不得与 MPRIS `player` 混用。
- 隔离检查入口使用 `*-check.qml`；纯模型辅助文件使用职责明确的 PascalCase 文件名。

## Git 工作流
- 提交信息使用简洁的 Conventional Commits 风格，例如 `feat: 增加音频输出设备选择`。
- 不自动推送远程仓库。

## 测试
- 新增 QML 组件必须通过 `qmllint -I /usr/lib/qt6/qml`。
- 状态与布局行为优先使用隔离 `*-check.qml` 验证，避免测试读写真实通知历史或执行危险系统动作。
- 涉及桌面视觉和硬件服务时，自动门禁之外还需在真实 Wayland 会话完成运行时加载或截图验收。
