# 控制中心音频输出设备选择 — 需求

确认后冻结，执行阶段不可修改。如需变更必须回到设计阶段重新确认。

## 核心目标
在点击右岛展开的控制中心中，为音量控制栏增加输出设备下拉选择，让用户能够直接选择当前用于播放声音的 PipeWire 输出设备。

## 功能边界
- 枚举 PipeWire 中可用的硬件音频输出节点，排除应用流、输入源和非音频节点。
- 在现有音量栏内显示当前默认输出设备，并提供下拉列表切换默认输出。
- 设备切换后，现有音量与静音控制继续作用于新的默认输出设备。
- 覆盖加载中、无设备、单设备、多设备、默认设备短暂为空和设备热插拔状态。

## 非目标
- 不新增输入设备选择。
- 不实现逐应用音频路由或移动单个现有音频流。
- 不重写现有基于 `wpctl` 的音量、静音与事件订阅链路。
- 不改变右岛入口、控制中心整体结构或 MPRIS 播放器选择逻辑。

## 技术约束
- 目标环境为 Arch Linux 上的 Quickshell 0.3.0、PipeWire/WirePlumber 与 Qt 6 QML。
- 使用 `Quickshell.Services.Pipewire` 的 `Pipewire.nodes`、`defaultAudioSink` 和 `preferredDefaultAudioSink`。
- 延续 `.helloagents/DESIGN.md` 的石墨黑灰阶、冰蓝强调色、JetBrains Mono 与紧凑工业控件语言。
- 不引入第三方依赖。

## 质量要求
- 设备过滤、标签回退、重复名称消歧和当前索引计算具备独立自动化检查。
- 新增 QML 通过 `qmllint`，现有布局/通知/托盘门禁不得回归。
- 下拉选择具备禁用态、可见焦点、键盘操作、长名称省略与受控展开高度。
- 真实 PipeWire 切换至少完成命令链路和运行时加载验证；无法在沙箱内完成的硬件行为必须明确记录。
