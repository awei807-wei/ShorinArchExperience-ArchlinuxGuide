# 贴顶反向圆角 Bar — 实施规划

## 目标与范围
在不改动功能层级的前提下，把当前带 `4px` 顶部留白的独立圆角岛改为贴住屏幕顶边的连续连接带 + 三个下伸功能区，并复刻 Brainitech/Brain_Shell 源码中的成对反 R 角拓扑。

## 架构与实现策略
- 新增轻量 `BarContour` Canvas 视觉组件，用一张全宽路径同时绘制顶部连接带和三个岛体，不承载状态或输入。
- `Bar.qml` 把 Context、Clock、System 的实际宽度与位置传给轮廓；左/右区在屏幕边缘闭合，中区保留双侧成对圆角。
- 现有功能组件继续承担内容和输入，默认表面切换为透明；hover 仍由原组件在连续底面上提供局部反馈。
- `SystemIsland` 增加集成表面模式，使 Metrics、Tray、Power 共用一个外轮廓，同时让 Tray 展开浮层继续使用独立实色表面。
- `shell.qml` 继续通过集中配置读取窗口边距，顶部值改为 `0`，窗口与内容高度统一为 `40px`。

## 领域语言
- **顶部连接带**：贴住屏幕顶边、横贯 Bar 窗口的 `6px` 连续窄表面。
- **主体底边**：下伸功能区的平直底边。
- **反 R 角**：`15px` 上部内凹圆角、短直边和 `15px` 下部外凸圆角组成的连续侧边；不是普通 `Rectangle.radius` 或单段椭圆。

## 完成定义
- Bar 窗口顶部边距为零，连接带第一行像素贴住屏幕顶边。
- 左区仅右侧成对圆角、中区双侧成对圆角、右区仅左侧成对圆角，曲线与连接带、短直边、平底均保持切线连续。
- 现有布局门禁、QML lint、运行时加载日志和真实截图均通过。
- `qaMode=deep`；重点检查透明接缝、窄屏轮廓相交、交互表面与托盘展开回归。

## 文件结构
- `components/BarContour.qml`：新增可复用反向圆角轮廓。
- `Bar.qml`：全宽轮廓与三个内容区的生产装配。
- `components/SystemIsland.qml`、`components/TrayIsland.qml`：连续右区表面兼容。
- `config/BarTuning.qml`、`shell.qml`：集中几何与贴顶窗口配置。
- `bar-layout-check.qml`：新增轮廓几何门禁。
- `.helloagents/DESIGN.md`、`.helloagents/modules/bar.md`、`.helloagents/CHANGELOG.md`：同步稳定设计契约与变更记录。

## UI / 设计约束
- 界面目的：在不增加信息密度的情况下，让顶部 Bar 像屏幕边缘的一体化硬件控制轨。
- 目标场景：当前 niri 主屏及既有多屏、窄屏响应式档位。
- 情绪方向：延续现有 Swiss industrial 克制感；记忆点改为从屏幕顶边自然下伸的三段轮廓。
- 顶部连接带、主体和轮廓使用既有 `surface` token，不添加渐变、阴影、发光或新强调色。
- 外轮廓统一，内部 hover、焦点、状态文字仍覆盖现有可用性要求。

## 风险与验证
- 风险：窄屏相邻转角在连接带下方相交。使用 Brain_Shell 的 `34px` 排除间距，并让中央岛仅在必要时向左避让；布局门禁覆盖阈值边界。
- 风险：透明化子组件后 Tray 展开表面丢失。集成模式仅影响折叠根表面，展开面单独保持原色与边框。
- 风险：分立 Shape 抗锯齿产生接缝。改用单个 Canvas 闭合路径一次填充所有区域，并对真实截图放大检查。
- 回退点：移除 `BarContour` 包装并恢复原组件表面注入即可回到独立圆角岛，不涉及状态数据迁移。

- [2026-08-25] 使用单个全宽 Canvas 路径复刻上游拓扑，并按本项目动态内容宽度传入三个岛体边界；这是比三个独立轮廓更接近上游且无接缝的实现。
